# サーバーなしの2台WebRTC実機テスト

## 前提
GitHub Pages配信版を両方のiPhone Safariで開く。サーバーはアプリ配信のみ。WebRTCは \`iceServers: []\` とし、STUN/TURN/シグナリングサーバーは不使用。環境により直接接続できない可能性がある。Safariとテザリングは実機で結果を確認するまで未検証。

## 2台接続
1. 親iPhoneで「みんなで」→「おとなが宇宙をつくる」。Offer QRが表示される。
2. 子iPhoneで「みんなで」→「こどもが参加する」→「QRコードを読み取る」、親の画面を読ませる。Safariのカメラ許可が必要。
3. 子iPhoneにAnswer QRが表示される。
4. 親iPhoneで「QRコードを読み取る」を押し、子のAnswer QRを読み取る。
5. 両方が「直接つながった」と表示され、宇宙画面へ移行する。
6. QRが読めない場合、コードをコピーしてメッセージやAirDrop等で送信し、相手側の入力欄に貼り付ける。コードは他人に共有しない。
7. 親と子で交互に描画し、光の軌跡・音・くじらが相手に届くことを確認する。

## 環境別チェック
- [ ] 自宅Wi-Fi（ルーターの端末間通信遮断なし）で双方向に接続できる。
- [ ] 親iPhoneのインターネット共有に子iPhoneが接続し、双方向通信できる。
- [ ] 端末上のローカル音が指の動作にすぐ反応する。
- [ ] iOS SafariでQRスキャン時に内蔵カメラの映像が表示される。
- [ ] WebRTC接続失敗時の表示と「接続をやり直す」が機能する。
- [ ] Safariで「ホーム画面に追加」してPWA起動できる。
- [ ] 初回オンライン読込後、オフラインでもアプリを起動できる（同一Wi-Fiは維持）。
- [ ] 2台のどちらも片方の音と軌跡を受信する。
- [ ] 実名は別端末に表示されない。
- [ ] 再読み込み後はQR交換のやり直しが必要なことを確認する。

**制約:** 最初の試作は2台のみ。IP/ICE候補をQRに含むため家族以外に共有しない。iOSのバックグラウンド制限では通信が切れる場合がある。接続後も中継サーバーは使わない。すべての同一LAN/テザリングでの成功は保証されない。
